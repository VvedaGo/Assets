## 3. Продукты и состав

- **PRD-01.** Для каждого продукта фиксируются название, аудитория/сценарий использования, категории содержимого, варианты, композиции, демо-сцены, зависимости и поддерживаемое окружение.
- **PRD-02.** Считать раздельно: позиции каталога, файлы моделей, уникальные меши, отдельные префабы, цветовые варианты и композиции. Композиция из существующих моделей не увеличивает количество уникальных моделей.
- **PRD-03.** Farm Market Lite — бесплатная выборка из Full, совместимая с ним по стилю и масштабу. Состав и взаимные ссылки проверяются перед выпуском.
- **PRD-04.** Каждый платный пак пригоден для самостоятельного использования. Для совместного демо с другим паком явно указывать необходимые продукты; базовое демо должно работать с содержимым поставки и объявленными зависимостями.
- **PRD-05.** Новые темы, цены, скидки и даты релизов в старых планах считаются предложениями до отдельной фиксации решения. Farm Nature, Farm Animals и Bundle пока относятся к будущему развитию.

- **ART-04.** Генерация изображения или 3D-заготовки не означает готовность ассета. Нужны проверка геометрии, материалов, масштаба и результата в Unity.
- **ART-05.** Этот стандарт относится к фермерской серии; отдельная будущая серия может иметь собственный визуальный стандарт.

## 5. Технические требования

| ID | Требование | Проверка |
|---|---|---|
| TECH-01 | Масштаб 1 Unity unit = 1 метр, Y вверх, Z вперёд; pivot у основания, если функциональность не требует шарнира | Сопоставление размеров в Unity; исключения для дверей, колёс и лопастей описаны |
| TECH-02 | Корневой transform префаба: scale `(1,1,1)`, rotation `(0,0,0)`; функциональные исключения описаны | Inspector и тест размещения |
| TECH-03 | Для каждого самостоятельного предмета есть префаб; существующее именование серии `FMS_<Category>_<Name>_<Variant>` сохраняется | Реестр файлов и отсутствие конфликтов имён |
| TECH-04 | Геометрия без видимых дыр, неверных нормалей, Z-fighting и артефактов; UV и материал соответствуют модели | Осмотр с нескольких сторон и при рабочем освещении |
| TECH-05 | Коллайдеры подходят назначению предмета; предпочтительны простые формы | Проверка коллизий, проходов и входов; содержимое композиций проверено |
| TECH-06 | Бюджеты tris, текстур и материалов задаются для каждого пака; реальные значения измеряются | Отчёт с минимумом/максимумом и итогами; отдельно LOD0 и остальные LOD |
| TECH-07 | LOD обязателен там, где предусмотрен спецификацией пака; переключения не ломают силуэт | Проверка наличия уровней и поведения LODGroup в Unity |
| TECH-08 | Подвижные части Farm Yard отделены и имеют корректный pivot, если это предусмотрено списком моделей | Проверка открытия/вращения; отделённый меш сам по себе не означает наличие анимации |
| TECH-09 | Точные версии Unity и render pipeline указаны для каждого релиза | Импорт и открытие демо в чистом проекте целевой версии |
| TECH-10 | Состав поставки отделён от служебных инструментов и материалов производства | Проверка экспортируемого пакета и его зависимостей |

Исходное окружение: в родительском проекте и FarmMarket указан Unity `6000.3.10f1`; в родительском manifest — URP `17.3.0`. Рабочая базовая цель для первого цикла проверки — Unity 6.3 / URP. Это чтение настроек, а не результат запуска Unity.

Unity 2021.3+, Built-in и HDRP нельзя объявлять поддерживаемыми только на основании старого плана или возможности конвертировать материалы. Каждая заявляемая конфигурация должна пройти отдельную проверку. Текущие материалы FarmMarket описывают URP; другие конфигурации остаются неподтверждёнными.

Одна палитра, 3–4 материала и размер до 30 MB — прежние цели оптимизации. Они не выполнены автоматически и не являются универсальным запретом для всей линейки. Для текущих паков сначала измерить затраты и принять решение по оптимизации. Заявление «mobile-ready» требует проверки на выбранном устройстве и согласованных показателях; целевые устройства и бюджеты пока не определены.

- **PKG-05.** Проверять импорт, компиляцию, материалы, префабы и демо по экспортированному пакету в чистом проекте. Фиксировать версию, дату, ошибки и результат Validator.

### 7.2. Состав Technical Details

- **META-03.** Для каждого пака заполнить все перечисленные пункты. Если характеристика отсутствует — написать `None` / `No`; если неприменима — `Not applicable` с краткой причиной. Непроверенные значения пометить в черновике и вынести на проверку до релиза.

| Блок | Необходимые данные |
|---|---|
| **Unique Assets / Prefabs** | Количество моделей/мешей, отдельных префабов, вариантов и композиций раздельно; сумма префабов. Указать, что считается уникальным ассетом |
| **Polygon Count** | Треугольники: min/max на модель для LOD0, среднее и сумма по уникальным моделям LOD0; для неоднородного набора — разбивка по категориям или моделям. Указать способ измерения и не суммировать повторные экземпляры композиций как новые модели |
| **LODs** | Есть ли LOD; число уровней, охват моделей и исключения; полигонаж или доли снижения по уровням |
| **Textures** | Количество, форматы, разрешения с распределением по размерам; типы карт (Base Color, Normal, Metallic и т. д.), наличие alpha и особенности атласов. Текстуры демо считать отдельно |
| **Materials / Shaders** | Количество материалов, используемые шейдеры и необходимые пайплайны; материалы демо считать отдельно |
| **UVs** | Наличие и число UV-каналов, использование палитры/атласов, особенности развёртки; lightmap UV, если они заявлены |
| **Rigging / Animations** | Статические или skinned-модели; есть ли rig, его тип; число и список анимаций. Отдельные двери/колёса не считать готовыми анимациями |
| **Colliders** | Наличие, типы и охват моделей; исключения и устройство коллайдеров крупных/составных объектов |
| **Scale / Setup** | Единицы масштаба, оси, расположение pivot, именование; особенности модульной сетки и подвижных частей |
| **Files / Sources** | Форматы моделей и прочих исходников; что включено и что не входит в поставку |
| **Demo / Scripts** | Названия и число сцен, назначение скриптов, управление и зависимости; какие вспомогательные материалы относятся только к демо |
| **Compatibility / Dependencies** | Проверенные версии Unity и render pipeline, обязательные пакеты и ограничения платформ. Значения должны совпадать с полями карточки |
| **Package Size** | Размер итогового экспортированного пакета с указанием версии; отличать его от размера папки проекта |

### 7.3. Проверка заполнения

- **META-04.** Каждое поле хранить отдельным подписанным блоком с готовым текстом для переноса в портал. Редакторские заметки, варианты, `TODO` и `[ПРОВЕРИТЬ]` держать отдельно от финального текста.
- **META-05.** Перед отправкой сверить ограничения длины Title и Summary, число тегов, доступные категории и остальные поля с текущей формой Publisher Portal. В локальном документе Lite для Summary записан диапазон 10–200 символов; до проверки формы использовать его только как рабочий ориентир.
- **META-06.** Сверять Summary, Description, Technical Details, README, Release Notes и цифры на изображениях с одной версией фактического реестра. Готовая карточка не содержит незаполненных полей и неподтверждённых обещаний; для опционального отсутствующего материала указан статус.
- **META-07.** При изменении состава или версии повторно проверить карточку. Если портал требует поле, отсутствующее в этом шаблоне, добавить его сюда и в карточку соответствующего пака.

### 7.6. Стиль изображений и расположение графики

**IMG-03. Основа по конкурентам.** В локальном разборе Searcher у Synty Simple Farm отмечены тёмная плашка с белым названием, цветная строка слогана, логотип слева и угловой бейдж; у Polyworks — единая рамка и повторяемая типографика; у 3DForge — коллажи для нескольких типов содержимого. Использовать эти принципы читаемости и единства серии. Цвета, логотип, шрифтовую композицию и формы оформить собственные. Это выводы сохранённого исследования, без нового просмотра текущих страниц конкурентов.

| Элемент | Наше правило |
|---|---|
| **Рендер** | Реальная модель/сцена пака в Unity, stylized low-poly, тёплая палитра серии, мягкий дневной свет и контактные тени. Без фотореалистичного шума и обработки, которая скрывает качество моделей. Дополнительные эффекты, не входящие в поставку, обозначены |
| **Фон** | Hero/Card/Cover — небо, спокойный цвет или сдержанный градиент с контрастом к предметам. Каталоги — единый светлый нейтральный фон, исходный ориентир `#E9E9EC`. Один тип фона на серию каталожных кадров; смена фона имеет понятную функцию |
| **Композиция** | Один главный фокус, предметы достаточно крупные, без больших пустых участков. Площадка Hero занимает примерно 80–90% доступной области рендера; место под текст учитывается отдельно. Избегать фонарей, столбов и ящиков, перекрывающих главный объект |
| **Название** | На Card и Cover — внизу слева на тёмной плашке, справа от логотипа при его наличии. Короткое узнаваемое имя в 1–2 строки; длинный поисковый подзаголовок из Package Title можно опустить. Например, `FARM MARKET STARTER` или `FARM YARD`; обозначение Lite остаётся видимым |
| **Основная плашка** | Тёмная, ориентир `#20242A`, текст белый/кремовый. Card: вместе с акцентной строкой 35–40% высоты; Cover: 20–25%. Это начальные пропорции — корректировать ради читаемости и сохранения главного объекта |
| **Акцентная строка** | Под названием — более узкая тёплая красная полоса, ориентир `#C8473B`, с одним коротким тезисом: `LOW POLY · URP` либо проверенное количество `119 PROPS + 6 COMPOSITIONS`. На Card выбирать один тезис; без длинных списков |
| **Шрифт** | Один жирный sans-serif для заголовков, один согласованный стиль для подписей; максимум два семейства. Condensed допустим при хорошем чтении. Без тонких начертаний, декоративных букв, лишних обводок и множества эффектов. Проверить право использования шрифта |
| **Логотип** | Собственный логотип слева внутри нижней плашки на Card/Cover, одинаковое относительное положение. На Icon/Social — опционально маленький знак в углу. Если логотип ещё не выбран, оставить в макете место и зафиксировать задачу; чужой знак не использовать |
| **Бейдж версии продукта** | На Card/Cover в верхнем левом углу небольшой акцентный бейдж: для Lite `FREE` или `LITE`, для платного — опционально `3D`. Не размещать одновременно несколько конкурирующих ярлыков. На Icon допустим один знак, если не ухудшает силуэт |
| **Бейдж обновления** | `UPDATE x.x` — только для реального выпущенного обновления на кадре с его содержимым. Не добавлять `NEW`, награды и показатели без основания |
| **Плашки галереи** | Внизу слева компактный тёмный блок/градиент: короткое имя пака и конкретная тема кадра (`FULL COLLECTION`, `STALLS & CRATES`, `LOD & COLLIDERS`). Ориентир высоты 8–12% кадра; не закрывать модели, каталожные подписи и Inspector |
| **Рамка** | Опциональная тонкая рамка/акцентный угол в цвете серии; применять одинаково. Не объединять в одном макете несколько разных конкурентных систем оформления |
| **Social** | Без рекламных полос и крупных надписей, с чистой композицией и небольшим запасом по краям. Название обычно сопровождает ссылку, поэтому основной объём кадра отдать сцене |

**IMG-04.** Lite и Full должны выглядеть одной линейкой: одинаковые шрифты, расположение плашек, логотип и обработка рендера. Их содержимое и бейджи соответствуют конкретной поставке. Нельзя показывать в Lite полный платный рынок как будто он входит в бесплатный пак. Farm Yard сохраняет общий визуальный код, но главным объектом становится постройка, а не овощи.

### 7.7. Иконки предметов внутри пака

**IMG-05.** Store Icon — одна иконка продукта из раздела 7.4. Иконки отдельных предметов для инвентаря/UI — отдельная опция поставки, которая пока не считается реализованной для всех паков. Если они включены в спецификацию продукта:

- Указать количество в карточке и вести соответствие «префаб → файл иконки». Базовое правило — одна иконка на самостоятельный предмет; отдельные цветовые/геометрические варианты получают свои иконки, если различие важно для выбора в UI. Композиции считать отдельно.
- Рабочий экспорт — PNG 256×256 с прозрачным фоном, мастер — 1024×1024. Для крупного UI при необходимости добавить 512×512; набор разрешений зафиксировать для всего пака.
- Единые ракурс сверху-сбоку, освещение, масштаб внутри категории и поля около 10%. Без названий, рекламных плашек, логотипов и запечённой подложки; предмет целиком в кадре.
- Именование `ICO_<PrefabName>.png`; отсутствие иконок не заменять превью из концептов. Обещание «icons included» допускается только после проверки готового набора.

Добавлено 2026-11-20 по опыту Farm Processing (72 модели, 8 композиций, 3 демо-сцены). Инструменты и порядок — [Tools/README.md](Tools/README.md).

- **PIPE-01. Источник модели.** Генераторы 3D не подключены: модели строятся процедурными скриптами Blender по одному референсу на ID. Blender запускается без интерфейса (`--background`), чтобы несколько сборок шли параллельно. Живой MCP — только для разового просмотра.
- **PIPE-02. Общие библиотеки.** Новый пак использует `Tools/blender/pack_common.py` и `pack_shapes.py`, а не копирует помощники предыдущего пака. Мелкие однотипные предметы собираются одним реестровым скриптом `-- <ID> build|export` (`build_registry_template.py`).
- **PIPE-03. Пилот и контракты.** До серии: 2–3 пилотных предмета разных типов и правило стыковки модулей (стены, полы, столбы: точный габарит, половинки столбов, высоты), которое скрипт проверяет при каждой сборке (`SNAP OK`).
- **PIPE-04. Референс важнее каталога.** Размеры каталога — ориентир; пропорции снимаются с референса в пикселях. Бюджет треугольников — мягкий потолок: настоящие отверстия и решётки допускают перерасход до ~2× с записью в спецификации.
- **PIPE-05. Дубли.** Перед каждой партией продуктов и мебели — сверка с моделями предыдущих паков; совпадающий предмет заменяется другим или явно отличается силуэтом.
- **PIPE-06. Ревью.** Каждая модель сверяется с референсом на парных листах (`compare_sheets.py`); итог — файл по шаблону `Tools/agents/REVIEW_TEMPLATE.md` (проходит / замечания / править / решение). Решения владельца записываются туда же.
- **PIPE-07. Один артефакт на модель.** В `art/<Pack>/Previews` — ровно одно превью; проверочные рендеры только во временной папке. Кадры для магазина — по одному рендеру без наложенного текста, если текст не заказан отдельно.
- **PIPE-08. LOD.** Встроенная генерация Mesh LOD Unity не используется для flat-атласов (размазывает цвета). LOD1 делает `make_lod1.py`; после любого переэкспорта модели LOD1 пересобирается.
- **PIPE-09. Unity.** Импорт, материалы, префабы с коллайдером и LODGroup — `PackPrefabBuilder` с отчётом `Documentation/ImportReport.txt`. Сцены, композиции и кадры — `PackSceneBuilder` из текстовых раскладок. Управление открытым редактором — `Tools/unity/unity_eval.sh`.
- **PIPE-10. Агенты.** Сложные одиночные модели отдаются внешним исполнителям по одной, с общим брифом `Tools/agents/EXTERNAL_WORKER_BRIEF.md` и спецификацией с числами. Два исполнителя не правят один файл одновременно. Правки ревью возвращаются тому, кто строил модель.
- **PIPE-11. Коммиты.** Коммит после каждой принятой партии моделей и после каждого шага Unity, а не в конце пака.
