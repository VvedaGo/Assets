## 1. Продукт и его место в серии

**Рабочее название магазина:** `Farm Processing - Low Poly Workshops & Production Props`.

Самостоятельный набор low-poly оборудования для переработки фермерского сырья: сыр, масло, сок, мука, варенье, сушёные продукты; расширение добавляет выпечку, растительное масло, копчение и мёд. Подходит для cozy farming, управления мастерскими, деревенских сцен и крафтовых игр.

Главный результат для покупателя: собрать узнаваемую производственную мастерскую из отдельных предметов или поставить готовую композицию. Оборудование должно читаться с игрового ракурса сверху-сбоку, а не только на крупном промо-рендере.

Связь серии: **Farm Nature — выращивание → Farm Processing — переработка → Farm Market — продажа**. Farm Yard даёт внешний двор и здания. Новый пак работает сам по себе; предыдущие продукты не являются зависимостями.

Наименование Processing описывает художественную тему. Пак не реализует экономику, рецепты, инвентарь, сохранения или физическую симуляцию переработки.

### 3.3. Визуальные цепочки переработки

| Зона | Последовательность показа | Что реально поставляется |
|---|---|---|
| Молочная | Чан → пресс → сыр в форме → стеллаж | Оборудование и предметы на последовательных местах; без моделирования молочной жидкости |
| Масло | Маслобойка → брусок на доске | Отдельный шток и готовый продукт |
| Сок | Дробилка → мезга → пресс → кувшин | Мезга и кувшин — свои модели; падающих яблок и потока сока нет |
| Мука / хлеб | Жернова → мука → тесто → печь / противень | Печь и готовая выпечка добавляются во второй волне |
| Варенье / сушка | Котёл → горшок; сушилка → лотки / травы | Готовые предметы можно заменять в собственном игровом коде |
| Масло семян | Пресс → жмых → бутылка | Вторая волна, без жидкостной симуляции |
| Копчение | Шкаф → подвесы рыбы и окорока | Вторая волна, дым не входит в базовое обещание |
| Мёд | Рамка → медогонка → горшок | Вторая волна, без пчёл и новой модели улья |

Сырьё из Nature и Market может показываться в отдельном совместном промо с подписью об источнике. В базовой сцене нового пака цепочка начинается с оборудования и промежуточных продуктов из его собственного состава; для неё не нужны купленные ранее яблоки, поля, животные или молочные бидоны.

## 4. Пересечения с предыдущими продуктами

Проверены местные планы и README Farm Yard / Farm Nature и публичное описание Farm Market. Перед генерацией нужен детальный осмотр фактических моделей еды Market: каталог указывает cheese, bread, honey/jam, milk и тару, но одних названий недостаточно для оценки одинаковой геометрии.

| Уже есть | Решение для нового набора |
|---|---|
| Овощи, фрукты, ящики, корзины, базовые бочки | Не делать ещё один общий каталог сырья и тары |
| Сыр, хлеб, молоко, банки мёда и варенья | Новые формы, связанные с процессом: сыр в форме, мезга, тесто, жмых, продукт на рабочем лотке. Сравнить силуэты и UV с Market |
| Дом, амбар, сарай, мельница, теплица | Не производить повторно здания; ручные жернова — внутренний прибор, а не новая башня мельницы |
| Улей | Только медогонка и рамка, без нового улья |
| Общие столы и полки рынка | Специализированные формы: каменная столешница сыродела, решётчатые сырные полки, стол розлива |
| Природа, грунт, тропы | Никакой зависимости: в поставке новые простые полы мастерской; растения из других паков только в помеченном совместном промо |

Если PRD или FUR совпадает с существующей моделью практически полностью, заменить её новым процессным предметом с тем же ID до фиксации референса. Не копировать старый FBX и не заявлять его новой уникальной моделью. Таблица 72 — целевой состав после такой сверки, а не повод сохранить дубли ради числа.

## 5. Визуальный стандарт

- Продолжать серию: крупные простые формы, умеренно округлённые края, читаемые силуэты, flat shading, без мелких декоративных винтиков.
- Палитра: дерево `#B5835A` / `#7A5233`, кремовый `#F2E6C9`, красный `#C8473B`, зелёный `#6E9F4A`, синий `#4A78A8`, металл `#8E959B`, камень `#A7A39A`. Медь котла — предложенный акцент `#B87945`, проверить рядом с предыдущими моделями.
- Конструкции выглядят пригодными к работе: толстые опоры, доступ к рукояткам, свободный ход плиты, реалистичный путь продукта от входа до выхода.
- Без этикеток и встроенного текста. Различать назначение формой, а не надписями.
- Жидкости и стекло: непрозрачные стилизованные поверхности, керамика/металл. Прозрачное стекло и реалистичные жидкости не добавлять в базовый объём.
- Референс предмета — один объект целиком на нейтральном фоне; сцену генерировать отдельно. Для механизмов дополнительно проверить вид сбоку и сзади.

### Пилот перед массовой генерацией

1. STA-02 — небольшой механизм: винт, пресс, раздельные детали.
2. STA-05 — главный объект: крупный силуэт, корзина, механика, носик.
3. MOD-04 — чистая архитектура и стыковка с MOD-03/06, простые проверочные части можно собрать вручную.

Пилот довести до FBX, материалов, prefab и тестового рендера, а не остановиться на красивой картинке. Критерии: стиль рядом с Market/Yard, корректные зазоры и pivots, приемлемая ручная доводка, читаемость с 8–12 м. По фактическому времени и цене пилота уточнить всю смету.

## 6. Техническая спецификация

| Параметр | Цель первого выпуска |
|---|---|
| Unity / pipeline | База существующей серии: Unity 6000.3.10f1 / URP 17.3.0; финальную совместимость подтверждать чистым импортом |
| Материалы | URP/Lit, непрозрачные; без сторонних шейдеров |
| Масштаб и оси | 1 unit = 1 м, Y вверх, Z вперёд |
| Root transform | Position zero, rotation identity, scale one |
| Именование | `FMS_Workshop_<Category>_<ID>`; категория и ID в CSV; внутренние детали суффиксами `_Handle`, `_Lid`, `_Plate` |
| Pivot | Пол — у основания; стена/балка — у точки стыка; вращающаяся деталь — на оси; дверь — на петле |
| Tris LOD0 | По каждой строке каталога: станции примерно 700–4000, инструменты 80–700, мебель 180–1400, модули 60–700 |
| LOD | Для всех 12 станций: LOD0 + LOD1, цель LOD1 около 45–60% LOD0 с сохранением силуэта; внутренние детали переходят согласованно. Для остальных 60 предметов LOD не планируется |
| Материалы / текстуры, бюджет | Цель до 8 общих материалов и до 8 Base Color атласов, обычно 256² / при необходимости 512²; это не результат измерения |
| UV | UV0 для палитры/атласа. Lightmap UV2 не обещать; демо на realtime lighting |
| Коллайдеры | Простые составные Box/Capsule; проёмы свободны, решётки не закрывают всю мастерскую невидимой стеной |
| Подвижные части | Отдельные дочерние transforms, без рига; список в каталоге |
| Анимация | Готовых клипов нет. Части подготовлены под вращение/перемещение пользователем |
| FBX | Исходники подготовленных моделей входят; нативные Blender-проекты в поставку не обещать |
| Размер | Мягкая цель экспорта до 80 MB; итог измерить |
| Зависимости | Только заявленное целевое Unity/URP; без других Asset Store паков |

Подвижные детали проверяются вручную поворотом/перемещением в редакторе. Пределы хода пресса, штока и дверей записать в README. Корневые объекты с подвижными детьми не помечать целиком Static.

Не обещать Built-in/HDRP, mobile-ready, универсальные FPS или автоматическую совместимость со всеми farming frameworks. Для таких обещаний нужна отдельная работа и проверка. Это не блокирует планирование URP-пака.

### Почему без готовых анимаций

Ценность первого релиза — оборудование, его конструкция и законченные рабочие зоны. В отличие от животных, станция убедительно выглядит и без постоянного движения. Отделение деталей позволяет покупателю подключить свои циклы. Изображения и ролик не должны показывать несуществующие включённые анимации. Если решим делать анимированную версию, завести отдельный объём на клипы, управление состояниями и проверку, затем пересчитать цену; сейчас он не включён.

## 9. Оценка труда и расходов на создание

### Труд

Оценка для полного выпуска одним исполнителем с генерацией части сложных заготовок и ручной подготовкой. Это не измеренный норматив и не оценка скорости автономного агента. Часы означают активную работу человека, ожидание очередей и модерации отдельно.

| Работа | Активных часов, оценка |
|---|---:|
| Сверка дублей, спецификация, пилот стиля | 8–12 |
| Выбор и исправление референсов | 10–16 |
| Сложные 3D-заготовки, повторы, отбор | 12–24 |
| Ручные модели, чистка, UV, раздельные детали и LOD | 30–50 |
| Unity, коллайдеры, реестр | 12–20 |
| Композиции и две сцены | 12–20 |
| Промо-рендеры, оформление, документация | 12–20 |
| Чистый импорт, исправления и релизная подготовка | 8–12 |
| **Итого** | **104–174 ч** |

При 35 продуктивных часах в неделю: примерно 3–5 недель до готовой загрузки; модерация не включена. Пересчитать после трёх пилотных предметов. Главная неопределённость — качество сгенерированных механизмов и объём ручного восстановления.

### Денежные расходы

Реальный тариф генератора и остаток наших кредитов не проверялись. Поэтому стоимость производства нельзя честно назвать точной суммой. Рабочий расчёт:

`C = N_image × P_image + N_3D × P_3D + дополнительные подписки + резерв`.

- Изображения: ориентир 80–120 попыток на 72 предмета с повторным использованием стилевых референсов; для простых модулей достаточно общих схем, поэтому не требуется отдельная дорогая генерация каждого ракурса.
- 3D: ориентир 36–60 попыток на 18–24 сложных предмета; остальные 48–54 предмета делать из простых форм. Это число генераций, не конечных моделей.
- **Пример чувствительности, не тариф сервиса:** 100 изображений по условным $0.15 + 50 3D-попыток по условным $0.60 + $15 резерва = **$60 денежных затрат**.
- Рабочий денежный резерв на планирование: **$40–100**, только при подходящих реальных тарифах и соблюдении лимитов. Это не разрешение расходовать деньги и не гарантия уложиться. На пилот закладывать до 10% фактически выделенного бюджета.
- Если пользуемся уже оплаченной подпиской, расход кредитов фиксируем отдельно; повторно не записываем полную подписку как новые денежные затраты.
- Если считать собственный труд по ставке R, полная себестоимость = денежные затраты + `(104–174) × R`. При чисто условных $15/ч и расходах $40–100 это **$1,600–2,710**. Собственный труд не бесплатен даже при дешёвой генерации.

Не покупать сервисы и не менять тариф без конкретной выбранной необходимости. После пилота заполнить реальные P_image / P_3D, число исправленных заготовок и часы на модель; если смета превышена, сначала сокращать extension, не качество подготовки.

3. Сырный и соковый прессы различаются силуэтом; винты/плиты/валы не срослись с рамой. Двери и съёмные лотки работают в заданном диапазоне.

6. Коллайдеры не перекрывают дверные проёмы; предметы корректно размещаются на полках и столах. Пол/стена/навес собираются без щелей и Z-fighting.
7. Экспорт проверен импортом в чистую целевую Unity/URP: нет ошибок компиляции, розовых материалов или missing scripts. Validator пройден; существенные замечания устранены.
